# План версии 0.3.0

Ориентировочный срок: 1-2 недели

---

## Задачи

### ✅ 1. Автосохранение при переключении объекта

**Источник:** `features.md` — Модуль 1: Ядро приложения

**Проблема:** При переключении на другой элемент дерева, несохранённые изменения в текущем элементе теряются.

**Решение:** При переключении автоматически сохранять изменения без предупреждения.

**Объём:** 1-2 дня

**Польза:** Пользователь перестанет терять данные при случайном клике по другому элементу. Базовое ожидание от современного редактора.

---

### ✅ 2. Дублирование уведомлений пользователя

**Источник:** `tech_issues.md`

**Проблема:** При выполнении операций показываются дублирующие уведомления — одно из main-процесса через IPC, второе из renderer.

**Решение:** Определить единый источник истины для уведомлений. Провести аудит и удалить дублирующие вызовы.

**Объём:** 0.5-1 день

**Польза:** Чистый интерфейс без визуального шума. Одно уведомление вместо двух одинаковых.

---

### ✅ 3. Кнопка "открыть папку объекта" + Отображение дополнительных файлов (блок)

**Источник:** `tech_issues.md` + `features.md` — Модуль 4: Описание Мира

**Проблема:**

- Кнопка "открыть папку объекта" не работает
- Пользователь не видит, какие файлы добавил в папку объекта

**Решение:**

- Исправить обработчик кнопки
- В `ContentDisplay` отображать список всех файлов в папке объекта (кроме `content.md`) с возможностью их открытия

**Объём:** 2-3 дня

**Польза:** Полноценная работа с дополнительными материалами (изображения персонажей, документы, заметки). Пользователь сможет: положить файл в папку → увидеть его в интерфейсе → открыть.

---

### ✅ 4. Массовое добавление пунктов плана

**Источник:** `features.md` — Модуль 3: Повествование

**Проблема:** Пользователю приходится добавлять каждый пункт плана вручную, что неудобно при переносе плана из внешнего источника.

**Решение:** Парсить вставленный текст и создавать несколько пунктов за раз — по одному на строку или в формате markdown-списка.

**Объём:** 1 день

**Польза:** Экономия времени при переносе плана. Вместо 20 кликов — одна вставка.

---

### ✅ 5. Рекурсивное удаление элементов повествования

**Источник:** `features.md` — Модуль 3: Повествование

**Проблема:** Чтобы удалить главу со сценами, нужно сначала удалить все сцены вручную.

**Решение:** Удалять родительский элемент вместе со всеми дочерними за одну операцию, с запросом подтверждения (показать что будет удалено).

**Объём:** 1 день

**Польза:** Удаление структуры любой глубины в один клик с пониманием последствий.

---

### 6. Строгая консистентность (Удаление файлов)

**Источник:** `features.md` — Модуль 1: Ядро приложения

**Проблема:** При удалении объекта из базы данных файлы на диске остаются, засоряя проект.

**Решение:** Удалять связанную папку и файлы объекта вместе с записью в базе, с предупреждением.

**Объём:** 1 день

**Польза:** Чистота файловой структуры проекта. Уверенность, что удаление действительно удаляет всё.

---

### 7. Изменение порядка элементов повествования + Интеллектуальная коррекция (блок)

**Источник:** `features.md` — Модуль 3: Повествование

**Проблема:** Пользователь не может изменить порядок глав/сцен в дереве повествования.

**Решение:**

- Реализовать drag-and-drop для изменения порядка элементов
- При невалидном перемещении (сцена на часть) — "интеллектуальная коррекция": поместить в подходящее место вместо ошибки

**Объём:** 3-5 дней

**Польза:** Полноценное управление структурой произведения. Возможность перетаскивать сцены между главами, главы между частями — с понятным поведением при ошибках.

---

## Итоговый объём

**Ориентировочно:** 10-14 дней

**Приоритеты:**

1. Задачи, блокирующие базовые сценарии (автосохранение, drag-and-drop)
2. Баги, раздражающие при каждом использовании (дублирование уведомлений, нерабочая кнопка)
3. Улучшения UX, экономящие время (массовое добавление, рекурсивное удаление)
