# Поэтапный план разработки

---

## ✅ Этап 1: Быстрые и полезные улучшения для автора

Эти функции относительно легко реализовать, но они принесут много пользы пользователю, улучшив основной сценарий работы — написание и экспорт текста.

1. ✅ **Сборка рукописи в единый файл (.md):**
    * **Задача:** Создать функцию, которая собирает контент из всех файлов повествования (в правильном порядке) и сохраняет его в один `.md` файл.
    * **Обоснование:** Ключевая функция для экспорта и вычитки готового произведения. Не требует сложного UI.

2. ✅ **Метаданные для повествования (План и Основная мысль):**
    * **Задача:** Добавить в модель данных и интерфейс для элементов повествования два новых поля: "План" (чек-лист) и "Основная мысль" (текстовое поле).
    * **Обоснование:** Простое расширение существующей функциональности, которое углубляет проработку сюжета.

---

## ✅ Этап 2: Расширение редактора шаблонов

Этот этап фокусируется на улучшении системы кастомизации объектов мира, делая ее более гибкой.

1. ✅ **Редактор шаблонов: Добавление полей:**
    * **Задача:** Реализовать в менеджере шаблонов возможность добавлять новые текстовые поля к существующим типам объектов.
    * **Обоснование:** Первый шаг к полноценному конструктору типов. Логически развивает уже существующую (упрощенную) систему.

2. ✅ **Комментарии к пользовательским полям:**
    * **Задача:** Добавить возможность указывать комментарий/подсказку для каждого поля в шаблоне, которая будет отображаться в UI.
    * **Обоснование:** Небольшое, но важное UX-улучшение, которое делается в связке с доработкой редактора шаблонов.

---

## ✅ Этап 3: Настройки проекта и готовые шаблоны

На этом этапе мы добавляем больше контента и настроек "из коробки", что улучшает опыт первого использования.

1. ✅ **Настройки проекта (имя автора и т.д.):**
    * **Задача:** Создать UI и логику для сохранения общих настроек проекта (например, имя автора).
    * **Обоснование:** Простая в реализации фича, закладывающая основу для будущих глобальных настроек.

2. ✅ **Предустановленные шаблоны объектов мира:**
    * **Задача:** Создать набор готовых шаблонов (`Квест`, `Магический предмет` и т.д.) и реализовать механизм их импорта в проект пользователя.
    * **Обоснование:** Обогащает программу контентом и служит основой для "Конструктора проекта".

---

## Этап 4: Гибкая структура повествования (Архитектурное изменение)

Это сложный этап, который требует серьезных изменений в ядре приложения, но открывает большие возможности для кастомизации.

1. **Гибкая иерархия повествования (по "масштабу"):**
    * **Задача:** Переработать логику отображения и управления деревом повествования так, чтобы она не была жестко привязана к структуре "Часть-Глава-Сцена", а зависела от настроек проекта.
    * **Обоснование:** Это крупное архитектурное изменение, которое нужно делать отдельно. Оно развяжет руки для более гибкой настройки проектов.

---

## Этап 5: Конструктор проекта

Финальный этап, который объединяет наработки предыдущих этапов в единый, удобный инструмент для начинающих пользователей.

1. **Конструктор проекта:**
    * **Задача:** Создать "мастер" (wizard), который при создании нового проекта позволит выбрать структуру повествования (на основе фичи из Этапа 4) и импортировать пакеты шаблонов (из Этапа 3).
    * **Обоснование:** Зависит от реализации предыдущих этапов. Является логическим завершением цикла по улучшению стартового опыта.

---

## ✅ Этап 6: Улучшение документации для пользователей и контрибьюторов

1. ✅ **Реструктуризация документации и создание руководства пользователя:**
    * **Задача:** Реорганизовать структуру документации проекта. `README.md` должен стать разводящей страницей. Создать `docs/DEVELOPER_GUIDE.md` из старого ридми и новое `docs/USER_GUIDE.md` для пользователей.
    * **Обоснование:** Это улучшит навигацию по проекту как для пользователей, так и для контрибьюторов, и решит проблему отсутствия документации для конечного пользователя.
