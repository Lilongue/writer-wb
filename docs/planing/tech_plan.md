# Технический план работ

Этот документ содержит список технических задач, направленных на улучшение архитектуры, читаемости и стабильности кода. Эти задачи не являются пользовательскими фичами, но важны для долгосрочного развития проекта.

---

## Актуальные задачи

1. **Валидация типов в `ProjectSettingsService`:**
    * **Проблема:** При сохранении настроек не производится проверка соответствия значения его типу (`'text'`, `'boolean'`, `'number'`). Это может привести к сохранению некорректных данных в БД (например, строки "abc" для числовой настройки).
    * **Решение:** В `ProjectSettingsService` перед сохранением добавить логику валидации и, возможно, приведения типов. На стороне UI также можно улучшить компоненты ввода (например, использовать `<InputNumber>` для типа `'number'`).

2. ✅ **Внедрение системы уведомлений об ошибках:**
    * **Проблема:** При возникновении ошибок пользователь не получает информации о том, что пошло не так.
    * **Решение:** Реализован глобальный механизм для отображения уведомлений (тостов или модальных окон) при перехвате ошибок в `try-catch` блоках или IPC-событиях. Включает `notificationService` в `renderer`, IPC-канал `show-error-notification` в `main`, `ErrorBoundary` и глобальные слушатели `unhandledrejection`.

3. ✅ **Запрет на создание вложенных проектов:**
    * **Проблема:** Попытка создать проект в уже существующей директории проекта приводит к закрытию текущего проекта и отмене создания нового без уведомления.
    * **Решение:** В `ProjectService` при создании проекта добавлена проверка с помощью `_validateProjectStructure`. Если выбранная директория уже является проектом, выводится предупреждение через `notificationService.showError`.

4. **Рефакторинг модального окна создания проекта:**
    * **Проблема:** Модальное окно имеет лишний второй шаг и не сбрасывает свое состояние после использования.
    * **Решение:** 1. Убрать второй шаг, если он не несет функциональной нагрузки. 2. Реализовать сброс состояния компонента `ProjectWizardModal` при его закрытии или повторном открытии.

5. **Исправление бага в дереве объектов:**
    * **Проблема:** При создании объекта (например, персонажа), когда родительская категория свернута, дерево объектов может отображаться как пустое.
    * **Решение:** После создания нового объекта принудительно обновлять и раскрывать соответствующую ветку в `WorldObjectTree`, чтобы обеспечить корректное отображение.

6. **Синхронизация имени в области просмотра:**
    * **Проблема:** Имя открытого в `ContentDisplay` элемента не обновляется при его переименовании в дереве.
    * **Решение:** Использовать `eventBus` для отправки события об обновлении элемента. `ContentDisplay` должен подписаться на это событие и обновлять свои данные при его получении.

7. **Синхронизация дерева при архивации шаблона:**
    * **Проблема:** Архивированный тип шаблона остается видимым в дереве объектов.
    * **Решение:** После архивации шаблона через `TemplateManager` инициировать событие, которое заставит `WorldObjectTree` обновить данные и скрыть объекты, связанные с архивированным шаблоном.

8. ✅ **Улучшение UX экспорта рукописи:**
    * **Проблема:** Экспорт всей рукописи не был доступен через главное меню, что снижало удобство доступа.
    * **Решение:** Добавлен пункт "Экспортировать всю рукопись" в главное меню "Повествование". Модифицирован `useNarrativeTreeData.ts` для обработки IPC-сообщения и вызова функции экспорта всей рукописи.
