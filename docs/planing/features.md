# Декомпозиция функционала и определение MVP

Этот документ содержит подробный перечень функционала, разделенный по модулям. Каждая фича помечена статусом ее включения в приложение.

**Обозначения:**

* ✅ **Реализовано.** Функционал, который уже есть в приложении.
* ❌ **Не реализовано.** Функционал, который будет добавлен в будущих версиях.
* ⚙️ **Запланировано к разработке.** Функционал, который будет реализован в одной из следующих версий.

---

## Модули

### Модуль 1: Ядро приложения

| Статус | Фича                                                                  | Примечание                                                              |
| :----: | --------------------------------------------------------------------- | ----------------------------------------------------------------------- |
|   ✅   | **Интеграция с внешним редактором** (кнопка "Открыть файл")           | Ключевая фича, ради которой создается приложение.                       |
|   ✅   | **Фоновое отслеживание изменений** в `.md` файлах                     | Техническое ядро, обеспечивающее работу с внешними редакторами.         |
|   ✅   | **Базовый 3-панельный интерфейс** (дерево проекта, контент, метаданные) | Необходимый минимум для удобной навигации и работы.                   |
|   ❌   | Полнотекстовый поиск по всем файлам                                   | (Сложность. На старте достаточно поиска по названиям и тегам).          |
|   ❌   | Настраиваемый интерфейс (перемещение, скрытие панелей)                | (Полировка. Можно отложить).                                            |
|   ❌   | Темы оформления (светлая/темная)                                      | (Полировка. Можно отложить).                                            |
|   ❌   | **Поддержка нескольких языков (интернационализация)**                 | (Сложность. Увеличивает время разработки MVP. Можно заложить архитектурно с `i18next`). |
|   ❌   | **Строгая консистентность (Удаление файлов)**                         | (Завершающий шаг). При удалении объекта из базы данных его связанная папка и файлы на диске также должны быть удалены (с предупреждением). |

### Модуль 2: Управление Проектом

| Статус | Фича                                     | Примечание                                                              |
| :----: | ---------------------------------------- | ----------------------------------------------------------------------- |
|   ✅   | **Создание нового проекта**              | Необходимо для начала работы.                                           |
|   ✅   | **Открытие существующего проекта**       | Необходимо для продолжения работы.                                      |
|   ✅   | Настройки проекта (имя автора и т.д.)    | (Расширение функционала). Позволяет настраивать общие параметры проекта, такие как имя автора. Может быть интегрировано с конструктором проекта. |
|   ❌   | **Учет типа поля для настроек (с разделением на тип данных и UI-подсказки)** | (Расширение функционала). В текущей реализации все настройки хранятся как строки, а тип данных и способ отображения смешаны. Необходимо разделить `type` (для валидации бэкенда) и `uiHint` (для отображения на фронтенде: 'readonly', 'file-path', 'text-input' и т.д.), чтобы обеспечить более удобный, безопасный и гибкий интерфейс. |
|   ❌   | Архивирование / Экспорт проекта в zip     | (Удобство. Не является критичным для основной функции).                 |
|   ⚙️   | **Настройки окружения** (путь к внешнему редактору)                   | (Удобство. В MVP используется редактор по умолчанию. Важно для power-users, но не критично для старта). |
|   ✅   | **Конструктор проекта**                                               | (Расширение функционала). При создании нового проекта запустить 'мастер', в котором можно выбрать структуру повествования и начальный набор объектов мира (например, импортировав 'пакет шаблонов' для фэнтези). |
|   ❌   | **Разделение файла проекта и каталога с его содержимым**              | (Архитектурное изменение). Переход к модели, где `.wwb` файл является основным файлом проекта, содержащим ссылки на данные, расположенные в отдельной папке. Отложено из Этапа 7 для снижения сложности и рисков. |
|   ⚙️   | **Опциональное создание подпапки для проекта**                       | (Улучшение UX). В мастере создания проекта добавить опцию (чекбокс), позволяющую создавать проект в подпапке с именем проекта внутри выбранной директории. |

### Модуль 3: Повествование

| Статус | Фича                                                              | Примечание                                                              |
| :----: | ----------------------------------------------------------------- | ----------------------------------------------------------------------- |
|   ✅   | **Создание / переименование / удаление** элементов (Часть, Глава) | Базовые CRUD-операции.                                                  |
|   ✅   | **Поддержка вложенной структуры** (например, Глава содержит Сцены) | Основа для организации произведения.                                    |
|   ❌   | **Изменение порядка** элементов (drag-and-drop)                   | (Сложность UX. Базовая реализация оказалась неудобной. Требует 'интеллектуальной коррекции' и более тщательной проработки). |
|   ❌   | **"Интеллектуальная коррекция"** при drag-and-drop                | (Улучшение UX. Вместо ошибки, система исправляет невалидное перемещение. Пример: Сцена, перетащенная на Часть, помещается в первую главу этой части). |
|   ✅   | **Гибкая иерархия повествования (по "масштабу")**                | (Расширение функционала). Пользователь сможет гибко настраивать иерархию повествования через конструктор проекта, выбирая, какие из предопределенных уровней (например, "Часть", "Глава", "Сцена") будут активны в его проекте. Это позволит пропускать ненужные уровни и отвязать UI от жестко заданных правил. Внутренне будет использоваться механизм, подобный числовому полю 'scale'. |
|   ❌   | Сквозной просмотр всей рукописи в одном окне                      | (Удобство. Пользователь может сделать это вручную, открыв файлы).       |
|   ❌   | **Управление контентом для иерархических элементов**               | (Улучшение UX). Позволяет определять, имеет ли родительский элемент (глава, часть) собственный контент (аннотацию) или является просто контейнером. |
|   ⚙️   | Подсчет слов / символов                                           | (Полировка. Легко добавляется позже).                                   |
|   ❌   | **Рекурсивное удаление элементов повествования**                      | (Улучшение UX). Позволяет удалять родительский элемент (главу, часть) вместе со всеми его дочерними элементами за одну операцию, с запросом подтверждения. |
|   ✅   | **Метаданные для повествования (План и Основная мысль)**             | (Расширение функционала). Добавить поля 'План' (в виде чек-листа) и 'Основная мысль'. |
|   ⚙️   | Отдельное поле "Заголовок для экспорта"                       | (Новая фича). Позволяет определить отдельный заголовок для каждого элемента повествования, который будет использоваться при экспорте, независимо от его названия. |

### Модуль 4: Описание Мира

| Статус | Фича                                                                    | Примечание                                                              |
| :----: | ----------------------------------------------------------------------- | ----------------------------------------------------------------------- |
|   ✅   | **Создание / переименование / удаление** объектов мира                  | Базовые CRUD-операции.                                                  |
|   ✅   | **Предустановленные типы объектов** ("Персонаж", "Локация")             | **Упрощение для MVP:** вместо конструктора даем готовые базовые типы.   |
|   ✅   | **Предустановленные шаблоны объектов мира**                            | (Удобство и обучение). Предоставить набор готовых шаблонов (например, 'Квест', 'Магический предмет'), которые можно импортировать в проект в конструкторе или менеджере шаблонов. |
|   ✅   | Поле "Название" и ссылка на `.md` файл для каждого объекта              | Минимально необходимая структура для любого объекта.                    |
|   ✅   | **Использование ID в путях к файлам объектов мира**                     | (Ключевое изменение для стабильности). Путь к файлам объекта мира должен использовать его уникальный ID, а не отображаемое имя, для предотвращения потери данных при переименовании. |
|   ✅   | **Пользовательские шаблоны/типы** объектов ("Заклинание", "Раса")       | (Упрощенная реализация в MVP). Пользователь может создавать типы и определять для них текстовые поля, согласно ADR-002. |
|   ✅   | **Комментарии к пользовательским полям**                          | (Улучшение UX). Позволяет добавлять описания или пояснения к полям, повышая их информативность. |
|   ❌   | **Разделение системного и отображаемого имени для типов** | (Тех. долг). Разделить `name` в `entity_templates` на `system_name` (неизменяемое, используется в коде) и `display_name` (можно менять). Это повысит стабильность и позволит в будущем безопасно переименовывать любые типы, включая типы повествования. |
|   ✅   | **Редактор шаблонов: Добавление полей**                             | (Часть функционала конструктора полей). Позволяет добавлять новые поля к существующим шаблонам объектов мира. |
|   ❌   | **Редактор шаблонов: Редактирование и удаление полей**                  | (Часть функционала конструктора полей). Позволяет изменять и удалять существующие поля в шаблонах. Отложено для снижения сложности. |
|   ❌   | Редактирование характеристик в UI (кроме названия)                      | (Зависит от конструктора полей, поэтому откладывается).                 |
|   ❌   | **Гибкий интерфейс для метаданных объекта**                             | (Улучшение UX). Заменить текущее табличное отображение полей на более компактный и адаптивный интерфейс (например, многоколоночное представление). |
|   ❌   | **Быстрый поиск/фильтрация объектов мира**                              | (Улучшение UX. Заменить дерево на панель с фильтруемым списком).        |
|   ✅   | **Сохранение состояния дерева объектов мира при обновлении**             | (Улучшение UX). Устранить схлопывание дерева объектов мира после их редактирования. Требует рефакторинга механизма обновления UI (ADR-004). |
|   ❌   | **Пресеты/пакеты шаблонов для мира**                                  | (Расширение функционала). Создать наборы предустановленных шаблонов для разных жанров (фэнтези, научная фантастика), которые можно быстро импортировать в проект. |
|   ❌   | **Страницы категорий с табличным представлением**                 | (Новая фича). Сделать заголовки категорий в дереве объектов кликабельными. По клику открывать страницу со списком всех дочерних объектов в виде таблицы с возможностью сортировки по атрибутам. |

### Модуль 9: Пользовательский опыт, Документация и Распространение

| Статус | Фича                                          | Примечание                                                                                                           |
| :----: | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
|   ✅   | **Базовая документация в репозитории**      | (Ключевой UX). Создание `USER_GUIDE.md` с описанием основного сценария работы для новых пользователей и контрибьюторов. |
|   ❌   | **Интерактивное обучение (Onboarding)**         | (Полировка). Пошаговый тур при первом запуске, который знакомит пользователя с основными элементами интерфейса и рабочим процессом. |
|   ❌   | **Справочный раздел в приложении**              | (Полировка). Раздел справки, объясняющий, как использовать различные функции. Может быть реализован как набор статей или FAQ. |
|   ❌   | **Сайт-визитка проекта**                        | (Маркетинг). Простой веб-сайт с описанием приложения, его возможностей и ссылкой на скачивание. Полезно для привлечения пользователей и дизайнеров. |
|   ❌   | **Автоматическая проверка обновлений**           | (Удобство). Приложение должно проверять наличие новой версии и уведомлять пользователя о возможности обновления.         |
|   ❌   | **Система обратной связи в приложении**         | (Удобство). Простая форма для отправки отчетов об ошибках или предложений по улучшению функционала.                    |
|   ✅   | **Окно "О программе"**                          | (Стандарт). Стандартное модальное окно, вызываемое из меню, с информацией о версии, авторе и названии приложения. |
