# План работ: "Design & Tech Clearing"

Этот документ описывает план работ по устранению технического долга и улучшению дизайна. Задачи сгруппированы по этапам для последовательной реализации.

## ✅ Этап 1: Критические технические исправления

На этом этапе мы сосредоточимся на исправлении наиболее критичных багов и обеспечении обратной связи с пользователем, чтобы предотвратить потерю данных и серьезное недопонимание со стороны пользователя.

* **Внедрение системы уведомлений об ошибках:**
  * **Проблема:** Приложение не информирует пользователя о возникающих ошибках, что создает ощущение нестабильности и непредсказуемости.
  * **Решение:** Реализовать глобальный механизм для отображения уведомлений (например, тостов или модальных окон) при перехвате ошибок.

* **Устранение багов синхронизации и создания:**
  * **Проблема:** UI не обновляется или работает некорректно после действий пользователя:
    * Создание проекта внутри другого приводит к сбою без предупреждения.
    * Новый объект не появляется в дереве, если категория была свернута.
    * Имя элемента не обновляется в области просмотра после переименования.
    * Архивированный шаблон остается видимым в дереве объектов.
  * **Решение:** Обеспечить принудительное обновление состояния соответствующих компонентов UI после выполнения указанных действий, используя `eventBus` или другие механизмы для синхронизации. Добавить проверки и предупреждения для некорректных действий (например, создание вложенного проекта).

## ✅ Этап 2: Улучшения UX (технические)

На этом этапе мы сосредоточимся на улучшении удобства использования и "полировке" основных взаимодействий, которые не являются критическими, но значительно влияют на общее впечатление от приложения.

* **Рефакторинг модального окна создания проекта:**
  * **Проблема:** Лишний шаг и не сбрасывающееся состояние модального окна создают плохое первое впечатление о продукте.
  * **Решение:** Убрать ненужный второй шаг и реализовать сброс состояния компонента `ProjectWizardModal` при его закрытии.

* **Улучшение UX создания рукописи:**
  * **Проблема:** Функция создания рукописи не очевидна и скрыта в контекстном меню.
  * **Решение:** Добавить пункт "Создать рукопись" в главное меню приложения (`menu.ts`) для быстрого и удобного доступа.

## ✅ Этап 3: Редизайн и улучшение UX

На этом этапе мы сосредоточимся на визуальной составляющей и удобстве использования интерфейса, приведя его к единому стилю и исправив множество мелких и крупных недочетов в дизайне.

### Глобальные улучшения стиля

* **Унификация отступов:**
  * **Проблема:** Различные отступы между элементами в разных частях приложения создают ощущение визуального беспорядка.
  * **Решение:** Провести ревизию всех основных компонентов и окон и применить единую систему отступов для достижения консистентности.

* **Приведение к единому языку:**
  * **Проблема:** В интерфейсе присутствуют надписи как на русском, так и на английском языке.
  * **Решение:** Проверить все компоненты, модальные окна и статические тексты и перевести всё на русский язык.

* **"Безрамочные" инпуты:**
  * **Проблема:** Стандартные поля ввода с постоянными рамками создают визуальный шум.
  * **Решение:** Применить глобальный стиль для всех полей ввода (`Input`, `Select` и т. д.), при котором рамка появляется только при фокусе.

### Улучшение ключевых компонентов

* **Переработка чек-листа:**
  * **Проблема:** Текущая реализация с чекбоксами неинтуитивна.
  * **Решение:** Заменить чекбоксы на статусы («План», «В работе», «Сделано») и сделать весь блок сворачиваемым.

* **Улучшение деревьев навигации:**
  * **Проблема:** Элементы в деревьях мелкие, а раскрытие дочерних узлов работает неинтуитивно.
  * **Решение:** Увеличить размер элементов для удобства чтения и взаимодействия. Сделать так, чтобы клик по элементу не только открывал его, но и раскрывал дочерние узлы.

### Унификация модальных окон и форм

* **Унификация модальных окон шаблонов:**
  * **Проблема:** Избыточное количество модальных окон для схожих действий с шаблонами.
  * **Решение:** Объединить функциональность создания, переименования и редактирования полей в единое модальное окно `TemplateEditorModal`.

* **Улучшение UX обязательных полей:**
  * **Проблема:** Индикаторы-звездочки являются устаревшим и загромождающим UI подходом.
  * **Решение:** Убрать индикаторы, вместо этого делая кнопку подтверждения неактивной, пока все обязательные поля не будут заполнены.

* **Визуальная чистка форм и модалов:**
  * **Проблема:** Множество мелких несоответствий: лишние кнопки закрытия, нерастянутые поля, отсутствие лейблов, некорректные подписи кнопок.
  * **Решение:** Удалить дублирующие кнопки «крестик», заставить поля ввода растягиваться на всю ширину, добавить недостающие лейблы, исправить подписи («Отмена» -> «Отменить»).

* **Консистентность кнопок и иконок:**
  * **Проблема:** Несогласованные иконки, отступы и названия кнопок.
  * **Решение:** Унифицировать иконку удаления, исправить отступы между кнопками в Template Manager, переименовать «Copy» в «Duplicate», пересмотреть иконку в поле «Связать с».

### Локальные улучшения

* **Переименование раздела «Основная мысль»:**
  * **Проблема:** Заголовок не совсем ясен.
  * **Решение:** Переименовать в «Описание» или «Краткое содержание».

* **Группировка заголовка «Связи» с кнопкой:**
  * **Проблема:** Кнопка «+» визуально оторвана от заголовка «Связи».
  * **Решение:** Расположить кнопку добавления непосредственно рядом с заголовком (`Связи [+]`).

## Этап 4: Новые возможности (Features)

На этом этапе мы добавим несколько новых, но относительно простых в реализации возможностей, которые улучшат гибкость и удобство использования приложения.

* **Учет типа поля для настроек проекта:**
  * **Задача:** Расширить функциональность настроек проекта, добавив поддержку различных типов данных (число, чекбокс) вместо хранения всего в виде строк.
  * **Решение:** Модифицировать `ProjectSettingsService` и UI (`ProjectSettingsModal.tsx`) для рендеринга и сохранения настроек в соответствии с их типом.

* **Настройка пути к внешнему редактору:**
  * **Задача:** Дать пользователю возможность самому указывать путь к исполняемому файлу текстового редактора.
  * **Решение:** Добавить новую настройку в «Настройки окружения» (пока можно в настройки проекта), которая позволит пользователю выбирать редактор.

* **Опциональное создание подпапки для проекта:**
  * **Задача:** При создании нового проекта в мастере создания добавить опцию (чекбокс), позволяющую создавать проект в подпапке с именем проекта внутри выбранной директории.
  * **Решение:** Добавить чекбокс в `ProjectWizardModal` и скорректировать логику в `FileSystemService` для учета этой опции.

* **Отдельный заголовок для экспорта:**
  * **Задача:** Позволить пользователю задавать для элементов повествования отдельный заголовок, который будет использоваться при экспорте, независимо от его рабочего названия в дереве.
  * **Решение:** Добавить новое поле в `narratives` и соответствующий инпут в `NarrativeDetails.tsx`. Обновить логику экспорта для использования этого поля.

* **Кнопка "Открыть папку объекта":**
  * **Задача:** Предоставить пользователю удобный способ открывать директорию объекта в системном файловом менеджере. Это позволит легко добавлять связанные файлы (например, изображения).
  * **Решение:** В заголовок `ContentDisplay` для объектов мира (`WorldObject`) добавить кнопку, которая будет выполнять команду открытия папки объекта (`world/<template_id>/<object_id>/`).

## ✅ Этап 5: Дизайн-рефакторинг (вторая итерация)

На этом этапе мы реализуем пул улучшений от дизайнера для повышения консистентности и удобства интерфейса.

* **Корректировка стилей полей ввода:**
  * **Задача:** Убрать глобальное применение "безрамочного" стиля для инпутов и применять его точечно только к таблице свойств объекта.

* **Унификация отображения свойств объекта:**
  * **Задача:** Создать единый компонент для отображения свойств объекта и внедрить его во все релевантные компоненты (`WorldObjectDetails`, `WorldObjectModal`).

* **Улучшение модального окна создания объекта:**
  * **Задача:** Упростить модальное окно, скрыв или убрав второстепенные.

* **Улучшение модального окна создания проекта:**
  * **Задача:** Улучшить отступы и выравнивание.

* **Редизайн импорта шаблонов:**
  * **Задача:** Заменить двухпанельный интерфейс на карточки с чекбоксами для выбора и возможностью фильтрации по выбранным.
