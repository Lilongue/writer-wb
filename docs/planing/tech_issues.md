# Технический долг и задачи по улучшению качества кода

Этот документ содержит список технических задач, направленных на улучшение архитектуры, читаемости и стабильности кода. Эти задачи не являются пользовательскими фичами, но важны для долгосрочного развития проекта.

---

|Задача|Проблема|Решение|
|:---|:---|:---|
|**Исправить регрессию в интеллектуальной коррекции вложенности при Drag-and-Drop**|Вопреки логике иерархии (Часть > Глава > Сцена), пользователю удается перетащить элемент низкого уровня (Сцена) напрямую в элемент высокого уровня (Часть), минуя обязательный промежуточный уровень (Глава). Это нарушает структуру повествования и свидетельствует о поломке механизма интеллектуальной коррекции.|Провести отладку и исправить логику в `narrativeReorderer.ts`. Механизм должен корректно определять невалидное перемещение и либо отклонять его, либо находить подходящий дочерний контейнер для элемента (например, помещать сцену в первую главу выбранной части).|
|**Запретить создание рекурсивных связей (объект с самим собой)**|В модальном окне добавления связи из списка потенциальных целей не отфильтровывается исходный объект, что позволяет создать связь объекта с самим собой. Это противоречит пункту 4.7 чеклиста и является нежелательным поведением.|В коде, который формирует список объектов для создания связи, необходимо добавить фильтр, исключающий из этого списка ID исходного объекта.|
|**Синхронизировать панель "Дополнительные файлы" с файловой системой**|Панель "Дополнительные файлы" не обновляет свое состояние, когда пользователь изменяет содержимое папки объекта на диске (например, добавляет или удаляет изображение). Изменения становятся видны только после полного переключения на другой объект и обратно, что создает рассинхронизацию между состоянием на диске и тем, что видит пользователь.|Продумать и реализовать эффективный механизм обновления списка дополнительных файлов. Следует рассмотреть разные подходы: отслеживание фокуса окна приложения, периодические проверки или другие методы, чтобы найти оптимальный баланс между скоростью отклика и производительностью.|
|**Очищать область просмотра при удалении выбранного объекта**|Если удалить объект, который в данный момент открыт в `ContentDisplay`, информация о нем не исчезает с экрана. `ContentDisplay` продолжает показывать устаревшие данные до тех пор, пока пользователь вручную не выберет другой объект или не снимет выделение.|Реализовать механизм сброса состояния выбора после удаления. 1. Функция, отвечающая за удаление объекта (вероятно, в хуках `useNarrativeTreeData` или `useWorldObjectTreeData`), должна после успешного выполнения операции проверить, совпадает ли ID удаленного объекта с ID объекта, который сейчас выбран (`selectedItem`). 2. Если ID совпадают, необходимо программно сбросить состояние выбора (например, вызвав `setSelectedItem(null)`). Это приведет к тому, что `ContentDisplay` очистится и покажет свое состояние по умолчанию ("ничего не выбрано").|
|**Предоставлять обратную связь при попытке архивации используемого шаблона**|При попытке заархивировать шаблон, который используется хотя бы одним объектом мира, операция молча не выполняется. Пользователь не получает никакого сообщения об ошибке или объяснения, почему архивация не произошла.|1. В `TemplateService`, перед выполнением операции архивации шаблона, добавить логику проверки. Сервис должен запросить у `WorldObjectDao`, существуют ли объекты мира, ссылающиеся на `id` данного шаблона. 2. Если такие объекты существуют, операция архивации должна быть прервана. 3. Сервис должен отправить пользователю уведомление об ошибке с понятным текстом, например: "Невозможно заархивировать шаблон, так как он используется объектами."|
|**Внедрить тримминг (обрезку пробелов) для вводимых пользователем текстовых полей**|Многие текстовые поля в приложении не обрезают начальные и конечные пробелы из вводимых строк. Это приводит к неаккуратному отображению имен и данных (например, `"  Мой объект"`) и может вызывать ошибки при поиске, сортировке или сравнении. Проблема точно замечена в редакторе шаблонов, но, вероятно, присутствует и в других формах.|Провести аудит и внедрить обрезку пробелов на двух уровнях: 1. **На стороне `renderer`:** Во всех формах и полях ввода (`input`, `textarea`) применять `.trim()` к значениям перед их отправкой в `main`-процесс. 2. **На стороне `main`:** В качестве основного правила защиты, все строковые данные, получаемые сервисами (`NarrativeService`, `WorldObjectService`, `TemplateService` и др.) от `renderer`-процесса через IPC, должны проходить через `.trim()` перед использованием или сохранением в базу данных.|
|**Запретить создание объектов повествования с пустым именем**|Приложение позволяет создавать объекты повествования с пустым именем. Это приводит к созданию файлов с некорректным именем (например, `.md`) и появлению "безымянных" элементов в дереве интерфейса, что сбивает пользователя с толку.|Внедрить валидацию на двух уровнях: 1. **На стороне `renderer`:** В модальном окне создания/редактирования объекта повествования сделать кнопку "Сохранить" неактивной, если поле имени пустое или содержит только пробелы. 2. **На стороне `main`:** В `NarrativeService.ts`, в методе `createNarrativeItem`, добавить проверку, что переданное `name` не является пустым. Если проверка не пройдена, возвращать ошибку и информировать пользователя, предотвращая создание записи.|
|**Использование ID для имен файлов повествования**|Имена файлов для объектов повествования генерируются на основе их названий (`slugify(name)`). При переименовании объекта файл на диске не переименовывается, что создает рассинхронизацию. Это также может привести к коллизиям имен, если у объектов одинаковые названия.|Изменить логику создания и поиска файлов повествования. Вместо `slugify(name).md` использовать `id.md` в качестве имени файла. Это обеспечит уникальность, стабильность и устранит необходимость в переименовании файлов.|
|**Сортировка настроек проекта**|Настройки проекта отсортированы в странном порядке, и разработчик не может легко изменить этот порядок.|Реализовать механизм, позволяющий разработчику задавать порядок следования настроек в интерфейсе.|
|**Тестирование бэкенда**|Отсутствуют юнит-тесты для ключевых бэкенд-сервисов (`ProjectService`, `NarrativeService`, `WorldObjectService`), что повышает риск регрессий.|Написать комплекты юнит-тестов для обеспечения стабильности и упрощения будущего рефакторинга.|
|**Рефакторинг хранения пользовательских полей (JSON -> Реляционная)**|Хранение определений полей и их значений в JSON-строках (согласно ADR-003) усложняет будущие операции, такие как удаление или переименование полей.|Провести рефакторинг хранения, перенеся данные в нормализованные реляционные таблицы (например, `template_fields` и `object_field_values`). Так как публичной версии не было, изменение можно внести напрямую в `schema.sql`.|
|**Кнопка "открыть папку объекта" не работает**|В области отображения контента не работает кнопка "открыть папку объекта".|Исследовать и исправить обработчик кнопки.|
|**Дублирование уведомлений пользователя**|При выполнении операций (создание проекта и др.) пользователю показываются дублирующие уведомления — одно из main-процесса через IPC, второе из renderer. Например, при создании проекта: `ProjectService.ts:116` отправляет info, а `App.tsx:133` показывает success. Это перегружает интерфейс.|Определить единый источник истины для уведомлений: либо renderer сам решает что показать после IPC-ответа, либо main-процесс полностью управляет уведомлениями, а renderer молчит. Провести аудит и удалить дублирующие вызовы.|
