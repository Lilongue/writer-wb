# Технический долг и задачи по улучшению качества кода

Этот документ содержит список технических задач, направленных на улучшение архитектуры, читаемости и стабильности кода. Эти задачи не являются пользовательскими фичами, но важны для долгосрочного развития проекта.

---

| Задача | Проблема | Решение |
| :------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Сортировка настроек проекта** | Настройки проекта отсортированы в странном порядке, и разработчик не может легко изменить этот порядок. | Реализовать механизм, позволяющий разработчику задавать порядок следования настроек в интерфейсе. |
| **Тестирование бэкенда** | Отсутствуют юнит-тесты для ключевых бэкенд-сервисов (`ProjectService`, `NarrativeService`, `WorldObjectService`), что повышает риск регрессий. | Написать комплекты юнит-тестов для обеспечения стабильности и упрощения будущего рефакторинга. |
| **Рефакторинг хранения пользовательских полей (JSON -> Реляционная)** | Хранение определений полей и их значений в JSON-строках (согласно ADR-003) усложняет будущие операции, такие как удаление или переименование полей. | Провести рефакторинг хранения, перенеся данные в нормализованные реляционные таблицы (например, `template_fields` и `object_field_values`). Так как публичной версии не было, изменение можно внести напрямую в `schema.sql`. |
| **Рефакторинг обработки ошибок** | Многие `try-catch` блоки и обработчики ошибок в коде сейчас просто выводят сообщение в консоль (`console.error`), что не информирует пользователя и не использует централизованную систему уведомлений. | Провести рефакторинг существующих `try-catch` блоков и других мест, где обрабатываются ошибки, заменив `console.error` на вызовы `notificationService.showError` (для ошибок, возникающих в `renderer`) или отправку IPC-сообщения через `notifyUserError` (для ошибок, возникающих в `main`). |

---

## Выполненные задачи

| Задача | Проблема | Решение |
| :------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Синхронизировать состояние выбора в деревьях** | Выделение элемента в одном дереве (Повествование) не снимается при выборе элемента в другом (Объекты мира). Это приводит к некорректному поведению: два элемента могут быть выбраны одновременно, а повторный клик по элементу снимает выделение, очищая область просмотра. | Реализовать механизм, который обеспечивает взаимоисключающий выбор между деревьями. При выборе элемента в одном дереве необходимо программно снимать выделение в другом, чтобы в приложении всегда был только один активный элемент. |
| **Переработка файловой структуры объектов мира** | Файловая структура для объектов мира (`world/<template_name>/<object_id>/content.md`) зависит от имени шаблона (`template_name`). При переименовании шаблона (что возможно для пользователя), пути к файлам всех связанных объектов мира становятся невалидными. Это приводит к потере контента или ошибкам "файл не найден". | Изменить способ формирования файлового пути, используя статический идентификатор шаблона (например, `template_id`) вместо его имени. Пример пути: `world/<template_id>/<object_id>/content.md`. Отказались от миграции существующих данных, т.к. не было публичной версии |
| **Ошибка создания директории при создании объекта из импортированного шаблона** | При импорте шаблона из библиотеки, приложение не создает для него соответствующую директорию на диске. В результате, при создании первого объекта этого типа, возникает ошибка `ENOENT`, так как приложение пытается создать поддиректорию для объекта внутри несуществующей директории шаблона. | Проблема была в недопустимых символах в имени шаблона. переименовали предустановленные шаблоны для, как временное решение проблемы |
| **Исправление бага в дереве объектов** | При создании объекта (например, персонажа), когда родительская категория свернута, дерево объектов может отображаться как пустое. | После создания нового объекта принудительно обновлять и раскрывать соответствующую ветку в `WorldObjectTree`, чтобы обеспечить корректное отображение. |
| **Рефакторинг модального окна создания проекта** | Модальное окно имеет лишний второй шаг и не сбрасывает свое состояние после использования. | 1. Убрать второй шаг, если он не несет функциональной нагрузки. 2. Реализовать сброс состояния компонента `ProjectWizardModal` при его закрытии или повторном открытии. |
| **Рефакторинг `GenericDao`** | `GenericDao` стал слишком большим, нарушая принцип единственной ответственности. | Разделение `GenericDao` на доменно-ориентированные DAO было завершено. |
| **Исправление адаптивности интерфейса** | Элементы управления накладывались друг на друга при изменении размера окна. | Верстка была исправлена для корректного отображения при любом разрешении. |
| **Унификация походов в базу** | Доступ к базе данных был разрознен и дублировался в разных сервисах. | Вся работа с базой данных была консолидирована через единый слой DAO. |
| **Брендирование файлов проекта и сборки** | Файлы проекта (например, `project.db`) имели стандартное расширение, а артефакты сборки — имена по умолчанию. | Расширение файла БД изменено на `.wwb`, и настроены параметры сборки для генерации артефактов с именем `WriterWorldBuilder`. |
| **Улучшение UX экспорта рукописи** | Экспорт всей рукописи не был доступен из главного меню. | Добавлен пункт "Экспортировать всю рукопись" в главное меню для быстрого доступа. |
| **Внедрение системы уведомлений об ошибках** | При возникновении ошибок пользователь не получает информации о том, что пошло не так. | Реализовать глобальный механизм для отображения уведомлений (например, тостов или модальных окон) при перехвате ошибок в `try-catch` блоках или IPC-событиях. |
| **Рефакторинг системы уведомлений** | IPC-каналы для уведомлений из `main`-процесса в `renderer` создаются для каждого типа уведомления (`show-error-notification`). Это не масштабируемо и приводит к дублированию кода в `renderer`-процессе для обработки каждого канала. | Создать единый `NotificationService` в `main`-процессе. Этот сервис будет использовать один IPC-канал (`show-notification`) для отправки всех типов уведомлений. Полезная нагрузка будет содержать тип уведомления (`error`, `warning` и т.д.), что позволит `renderer`-процессу централизованно обрабатывать и отображать их. |
| **Запрет на создание вложенных проектов** | Попытка создать проект в уже существующей директории проекта приводит к закрытию текущего проекта и отмене создания нового без уведомления. | В `ProjectService` при создании проекта добавлена проверка с помощью `_validateProjectStructure`. Если выбранная директория уже является проектом, выводится предупреждение через `notificationService.showError`. |
| **Синхронизация дерева при архивации шаблона** | Архивированный тип шаблона остается видимым в дереве объектов. | После архивации шаблона через `TemplateManager` инициировать событие, которое заставит `WorldObjectTree` обновить данные и скрыть объекты, связанные с архивированным шаблоном. |
| **Синхронизация имени в области просмотра** | Имя открытого в `ContentDisplay` элемента не обновляется при его переименовании в дереве. | Проблема решена удалением возможности переименования из контекстного меню деревьев. Переименование централизовано в `ContentDisplay`, где обновление дерева уже работает корректно. |
| **Переработать кнопку 'Открыть во внешнем редакторе'** | Текущая кнопка 'Открыть во внешнем редакторе' в `FileContent` была слишком громоздкой и перекрывала контент, а ее дизайн и расположение были неоптимальны. | Кнопка была перенесена в заголовок `ContentDisplayHeader`, что улучшило ее расположение и внешний вид, а также предотвратило наложение на контент. Старая кнопка из `FileContent` была удалена. |
| **Использование `boolean` типа для `is_visible` в шаблонах** | Поле `is_visible` хранится как `0` или `1` (число) в базе данных и обрабатывается как таковое в коде, что неявно и подвержено ошибкам. | Рефакторинг `is_visible` в таблице `entity_templates` на булевый тип (`BOOLEAN` или `INTEGER(1)` с явным указанием `TRUE`/`FALSE` или `0`/`1` и приведение в коде к `boolean`). Обновить все места, где используется `is_visible`, для работы с `boolean` типом. |
| **Использование перечислений (Enums)** | В коде используются "магические строки" (например, `'narrative'`, `'world'`) для идентификации типов, что снижает надежность и читаемость. | Провести рефакторинг, заменив строки на TypeScript Enums для повышения надежности, улучшения читаемости кода и автодополнения при разработке. |
| **Странное поведение модала настроек проекта без открытого проекта** | При не открытом проекте модал с настройками проекта выглядит странно. | Открытие модала настроек проекта теперь блокируется в меню, если проект не открыт. |
