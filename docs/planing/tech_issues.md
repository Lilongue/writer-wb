# Технический долг и задачи по улучшению качества кода

Этот документ содержит список технических задач, направленных на улучшение архитектуры, читаемости и стабильности кода. Эти задачи не являются пользовательскими фичами, но важны для долгосрочного развития проекта.

---

## Актуальные задачи

| Задача                                                              | Проблема                                                                                                                                     | Решение                                                                                                                                                                                                                       |
| :------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Валидация типов в `ProjectSettingsService`**                      | При сохранении настроек не производится проверка соответствия значения его типу (`'text'`, `'boolean'`, `'number'`). Это может привести к сохранению некорректных данных в БД (например, строки "abc" для числовой настройки). | В `ProjectSettingsService` перед сохранением добавить логику валидации и, возможно, приведения типов. На стороне UI также можно улучшить компоненты ввода (например, использовать `<InputNumber>` для типа `'number'`). |
| **Рефакторинг `GenericDao`**                                        | `GenericDao` стал слишком большим, нарушая принцип единственной ответственности. Он управляет доступом к данным для всех доменов (повествование, мир, шаблоны, настройки), что усложняет поддержку. | Разделить `GenericDao` на несколько доменно-ориентированных DAO (например, `NarrativeDao`, `WorldObjectDao`). Детальный план см. в [`refactoring_plan_dao.md`](../refactoring_plan_dao.md).                                   |
| **Использование перечислений (Enums)**                              | В коде используются "магические строки" (например, `'narrative'`, `'world'`) для идентификации типов, что снижает надежность и читаемость.      | Провести рефакторинг, заменив строки на TypeScript Enums для повышения надежности, улучшения читаемости кода и автодополнения при разработке.                                                                              |
| **Тестирование бэкенда**                                            | Отсутствуют юнит-тесты для ключевых бэкенд-сервисов (`ProjectService`, `NarrativeService`, `WorldObjectService`), что повышает риск регрессий. | Написать комплекты юнит-тестов для обеспечения стабильности и упрощения будущего рефакторинга.                                                                                                                              |
| **Рефакторинг хранения пользовательских полей (JSON -> Реляционная)** | Хранение определений полей и их значений в JSON-строках (согласно ADR-003) усложняет будущие операции, такие как удаление или переименование полей. | Провести рефакторинг хранения, перенеся данные в нормализованные реляционные таблицы (например, `template_fields` и `object_field_values`). Так как публичной версии не было, изменение можно внести напрямую в `schema.sql`. |

## Выполненные задачи

| Задача                             | Проблема                                                                        | Решение                                                                    |
| :--------------------------------- | :------------------------------------------------------------------------------ | :------------------------------------------------------------------------- |
| **Исправление адаптивности интерфейса** | Элементы управления накладывались друг на друга при изменении размера окна.     | Верстка была исправлена для корректного отображения при любом разрешении.  |
| **Унификация походов в базу**          | Доступ к базе данных был разрознен и дублировался в разных сервисах.            | Вся работа с базой данных была консолидирована через единый слой DAO.      |
