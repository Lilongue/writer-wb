# Архив выполненных технических задач (2025)

|Задача|Проблема|Решение|Дата выполнения|
|:-------------------------------------|:------------------------------------------|:-----------------------------|:---|
|**Переработка файловой структуры объектов мира**|Файловая структура для объектов мира (`world/<template_name>/<object_id>/content.md`) зависит от имени шаблона (`template_name`). При переименовании шаблона (что возможно для пользователя), пути к файлам всех связанных объектов мира становятся невалидными. Это приводит к потере контента или ошибкам "файл не найден".|Изменить способ формирования файлового пути, используя статический идентификатор шаблона (например, `template_id`) вместо его имени. Пример пути: `world/<template_id>/<object_id>/content.md`. Отказались от миграции существующих данных, т.к. не было публичной версии|28.01.2026|
|**Переработать кнопку 'Открыть во внешнем редакторе'**|Текущая кнопка 'Открыть во внешнем редакторе' в `FileContent` была слишком громоздкой и перекрывала контент, а ее дизайн и расположение были неоптимальны.|Кнопка была перенесена в заголовок `ContentDisplayHeader`, что улучшило ее расположение и внешний вид, а также предотвратило наложение на контент. Старая кнопка из `FileContent` была удалена.|28.01.2026|
|**Ошибка создания директории при создании объекта из импортированного шаблона**|При импорте шаблона из библиотеки, приложение не создает для него соответствующую директорию на диске. В результате, при создании первого объекта этого типа, возникает ошибка `ENOENT`, так как приложение пытается создать поддиректорию для объекта внутри несуществующей директории шаблона.|Проблема была в недопустимых символах в имени шаблона. переименовали предустановленные шаблоны для, как временное решение проблемы|27.01.2026|
|**Исправление бага в дереве объектов**|При создании объекта (например, персонажа), когда родительская категория свернута, дерево объектов может отображаться как пустое.|После создания нового объекта принудительно обновлять и раскрывать соответствующую ветку в `WorldObjectTree`, чтобы обеспечить корректное отображение.|15.01.2026|
|**Рефакторинг модального окна создания проекта**|Модальное окно имеет лишний второй шаг и не сбрасывает свое состояние после использования.|1. Убрать второй шаг, если он не несет функциональной нагрузки. 2. Реализовать сброс состояния компонента `ProjectWizardModal` при его закрытии или повторном открытии.|15.01.2026|
|**Синхронизация дерева при архивации шаблона**|Архивированный тип шаблона остается видимым в дереве объектов.|После архивации шаблона через `TemplateManager` инициировать событие, которое заставит `WorldObjectTree` обновить данные и скрыть объекты, связанные с архивированным шаблоном.|14.01.2026|
|**Синхронизация имени в области просмотра**|Имя открытого в `ContentDisplay` элемента не обновляется при его переименовании в дереве.|Проблема решена удалением возможности переименования из контекстного меню деревьев. Переименование централизовано в `ContentDisplay`, где обновление дерева уже работает корректно.|14.01.2026|
|**Запрет на создание вложенных проектов**|Попытка создать проект в уже существующей директории проекта приводит к закрытию текущего проекта и отмене создания нового без уведомления.|В `ProjectService` при создании проекта добавлена проверка с помощью `_validateProjectStructure`. Если выбранная директория уже является проектом, выводится предупреждение через `notificationService.showError`.|04.01.2026|
|**Улучшение UX экспорта рукописи**|Экспорт всей рукописи не был доступен из главного меню.|Добавлен пункт "Экспортировать всю рукопись" в главное меню для быстрого доступа.|03.01.2026|
|**Внедрение системы уведомлений об ошибках**|При возникновении ошибок пользователь не получает информации о том, что пошло не так.|Реализовать глобальный механизм для отображения уведомлений (например, тостов или модальных окон) при перехвате ошибок в `try-catch` блоках или IPC-событиях.|03.01.2026|
|**Брендирование файлов проекта и сборки**|Файлы проекта (например, `project.db`) имели стандартное расширение, а артефакты сборки — имена по умолчанию.|Расширение файла БД изменено на `.wwb`, и настроены параметры сборки для генерации артефактов с именем `WriterWorldBuilder`.|28.12.2025|
|**Рефакторинг `GenericDao`**|`GenericDao` стал слишком большим, нарушая принцип единственной ответственности.|Разделение `GenericDao` на доменно-ориентированные DAO было завершено.|27.12.2025|
|**Унификация походов в базу**|Доступ к базе данных был разрознен и дублировался в разных сервисах.|Вся работа с базой данных была консолидирована через единый слой DAO.|17.11.2025|
|**Исправление адаптивности интерфейса**|Элементы управления накладывались друг на друга при изменении размера окна.|Верстка была исправлена для корректного отображения при любом разрешении.|03.11.2025|
