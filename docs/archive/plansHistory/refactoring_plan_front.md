# План рефакторинга фронтенд-компонентов

Этот документ описывает планируемые задачи по рефакторингу ключевых компонентов React в приложении.

## 1. Компонент `WorldObjectTree` (Приоритет: Высокий)

**Расположение:** `src/renderer/components/WorldObjectTree.tsx`

### Проблема WorldObjectTree

Компонент нарушает Принцип единственной ответственности (Single Responsibility Principle). Его текущий размер (более 400 строк) и количество обязанностей делают его сложным для поддержки и тестирования.

Основные обязанности, совмещенные в одном файле:

- Отображение дерева.
- Загрузка и управление данными через IPC.
- Управление сложным внутренним состоянием (дерево, модальные окна, контекстное меню).
- Рендеринг и логика контекстного меню.
- Рендеринг и логика универсального модального окна для создания, переименования и удаления.

### План рефакторинга WorldObjectTree

1. **Создать новую структуру папок** для инкапсуляции всей логики, связанной с `WorldObjectTree`.

    ```text
    src/renderer/components/
    └── WorldObjectTree/
        ├── index.ts                     // Ре-экспорт основного компонента
        ├── WorldObjectTree.tsx          // Основной, "чистый" компонент-оркестратор
        ├── useWorldObjectTreeData.ts    // Кастомный хук для всей логики данных
        └── components/
            ├── WorldObjectModal.tsx     // Выделенный компонент модального окна
            └── TreeContextMenu.tsx      // Выделенный компонент контекстного меню
    ```

2. **Вынести логику данных в кастомный хук (`useWorldObjectTreeData.ts`)**:
    - Переместить всю логику `useEffect`, связанную с `ipcRenderer`.
    - Переместить функции для загрузки данных (`fetchWorldObjectTypes`, `onLoadData`).
    - Хук должен возвращать `treeData`, `expandedKeys`, `onExpand`, `loadData` и другие необходимые функции для управления данными.

3. **Выделить модальное окно (`WorldObjectModal.tsx`)**:
    - Компонент будет отвечать только за отображение и логику модального окна.
    - Он будет принимать пропсы, такие как `open`, `type`, `node`, и колбэки `onOk`, `onCancel`.
    - Внутренняя логика формы (поля ввода, состояние) будет инкапсулирована в этом компоненте.

4. **Выделить контекстное меню (`TreeContextMenu.tsx`)**:
    - Компонент будет принимать `node` и вызывать колбэк с выбранным действием.

5. **Обновить `WorldObjectTree.tsx`**:
    - Основной компонент будет использовать хук `useWorldObjectTreeData`.
    - Его разметка будет состоять из дочерних компонентов (`TreeContextMenu`, `Tree`, `WorldObjectModal`), а сам он будет выполнять роль оркестратора.

6. **Создать `index.ts`**: Добавить файл для удобного экспорта `export { default } from './WorldObjectTree';`, чтобы импорты в других частях приложения остались прежними.

## 2. Компонент `ContentDisplay` (Приоритет: Высокий)

**Расположение:** `src/renderer/components/ContentDisplay.tsx`

### Проблема ContentDisplay

Компонент является вторым "монолитом" в приложении с более чем 400 строками кода. Он перегружен обязанностями, что делает его крайне сложным для понимания и модификации.

Основные обязанности:

- Загрузка данных для любого типа сущности (`get-item-details`).
- Управление состоянием редактирования (`details` vs `editedDetails`).
- Сохранение изменений с разной логикой для разных типов сущностей.
- **Опрос файловой системы через `setInterval`** для отслеживания внешних изменений.
- Управление списком связей (CRUD).
- Реализация поиска с `debounce` для модального окна.
- Массивный условный рендеринг для разных типов сущностей и состояний.

### План рефакторинга ContentDisplay

1. **Создать структуру папок `ContentDisplay/`**.

2. **Выделить логику в кастомные хуки**:
    - `useItemDetails.ts`: Для инкапсуляции всей логики работы с данными: загрузка, опрос ФС, функции-действия (`createFile`, `deleteConnection`, `saveDetails`).
    - `useItemEditor.ts`: Для управления состоянием редактирования (`editedDetails`), хендлеров `onChange` и вычисления `isChanged`.

3. **Декомпозировать UI на дочерние компоненты** внутри `ContentDisplay/components/`:
    - `ContentDisplayHeader.tsx`: Заголовок с полем имени и кнопками действий.
    - `WorldObjectDetails.tsx`: Секция полей для `world object`.
    - `NarrativeDetails.tsx`: Секция полей для `narrative` (`description`, `ChecklistEditor`).
    - `ConnectionsManager.tsx`: Секция для управления связями, включая модальное окно.
    - `FileContent.tsx`: Компонент для отображения `ReactMarkdown` или кнопки "Создать файл".

4. **Обновить `ContentDisplay.tsx`** до компонента-оркестратора, который использует хуки и композирует дочерние UI-компоненты.

## 3. Компонент `ChecklistEditor` (Приоритет: Низкий)

**Расположение:** `src/renderer/components/ChecklistEditor.tsx`

### Проблема ChecklistEditor

Компонент смешивает логику рендеринга React с чистой логикой преобразования данных (парсинг/сериализация markdown).

### План рефакторинга ChecklistEditor

1. **Вынести функции `parseMarkdown` и `serializeToMarkdown`** в отдельный файл-хелпер `src/common/checklistUtils.ts`.
2. Импортировать и использовать эти утилиты в `ChecklistEditor.tsx`.

Это улучшит разделение ответственности (separation of concerns) и сделает компонент более сфокусированным на UI.

## 6. Компонент `TemplateManagerModal` (Приоритет: Средний)

**Расположение:** `src/renderer/components/TemplateManagerModal.tsx`

### Проблема TemplateManagerModal

Компонент представляет собой "модальное окно в модальном окне", что является анти-паттерном. Он совмещает в себе логику отображения списка шаблонов ("менеджер") и логику их редактирования ("редактор").

### План рефакторинга TemplateManagerModal

1. **Создать папку `src/renderer/components/TemplateManager/`**.
2. **Выделить "внутреннее" модальное окно** в отдельный компонент `TemplateEditorModal.tsx`. Этот компонент будет инкапсулировать всю логику `Form` для создания, копирования и редактирования шаблонов.
3. **Выделить логику получения данных** в кастомный хук `useTemplates.ts`. Он будет отвечать за загрузку списка шаблонов и их архивацию.
4. **Обновить `TemplateManagerModal.tsx`**: он станет "менеджером", который использует хук `useTemplates` для получения данных и управляет видимостью `TemplateEditorModal`.
