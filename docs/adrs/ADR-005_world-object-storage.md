# ADR-005: Переход на использование ID шаблона для файловой структуры объектов мира

* **Статус:** Принято
* **Дата:** 2026-01-27

## Контекст

Текущая файловая структура для хранения контента объектов мира (`content.md`) использует имя шаблона в пути: `world/<template_name>/<object_id>/content.md`.
Это создает две серьезные проблемы:

1. **Невалидные символы:** Имена шаблонов могут содержать символы, недопустимые для имен директорий в некоторых операционных системах (например, `:` в Windows). Это приводило к ошибкам `ENOENT` при создании директорий. (Проблема временно решена правкой имен в `predefined-templates.json`).

2. **Рассинхронизация при переименовании:** При переименовании шаблона в интерфейсе приложения, соответствующая директория на диске **не переименовывается**. Это создает рассинхронизацию: в UI у шаблона новое имя, а на диске — старое. Такое поведение неинтуитивно и затрудняет ручное управление файлами.

**Примечание:** Аналогичная проблема рассинхронизации существует и для объектов Повествования, однако их иерархическая структура хранения требует отдельного рассмотрения и решения.

## Решение

Изменить схему формирования пути к файлам объектов мира. Вместо имени шаблона (`template_name`) использовать его уникальный и неизменяемый идентификатор (`template_id`).

Новая структура пути будет выглядеть так: `world/<template_id>/<object_id>/content.md`.

## Последствия

### Положительные

* **Стабильность:** Пути к файлам больше не будут зависеть от изменяемых пользователем данных (имени шаблона), что полностью решает проблему "потери" файлов при переименовании.
* **Надежность:** Использование `template_id` (число) исключает появление невалидных символов в именах директорий, решая проблему с ошибками `ENOENT`.
* **Предсказуемость:** Структура на диске становится более строгой и предсказуемой для программной обработки.

### Отрицательные

* **Несовместимость:** Решение не предполагает миграции данных. Проекты, созданные до этого изменения, не будут совместимы с новой версией, что приемлемо на данном этапе разработки.
* **Читаемость файловой системы:** Директории вида `world/1/` менее информативны. **Однако, этот недостаток будет полностью компенсирован.**

### Компенсирующие меры

* Для устранения проблемы с нечитаемыми именами папок, в интерфейс `ContentDisplay` будет добавлена **кнопка "Открыть папку"**, которая будет открывать директорию, соответствующую объекту, в системном файловом менеджере. Это предоставит пользователю прямой доступ к файлам объекта и возможность добавлять связанные материалы (например, изображения).
