# ADR-006: Выбор способа изменения порядка элементов повествования

**Статус:** Принято

**Дата:** 2026-03-02

## Контекст

Приложению требуется функциональность для изменения порядка и уровня вложенности элементов в дереве повествования (глав, сцен и т.д.). Иерархия этих элементов является динамической и определяется свойством `weight`, заданным в шаблонах: чем больше `weight`, тем выше элемент в иерархии. Необходимо было выбрать метод, который был бы одновременно интуитивно понятным для пользователя, достаточно гибким для сложных структур и реализуемым в разумные сроки.

## Принятое решение

Выбран основной способ: **Перетаскивание (Drag-and-Drop) с "интеллектуальной автокоррекцией"**.

Пользователь перетаскивает элементы в дереве. Бэкенд-логика анализирует конечное положение. Если перемещение нарушает правила иерархии (основанные на `weight`), система не выдает ошибку, а автоматически корректирует положение элемента, пытаясь выполнить наиболее вероятное намерение пользователя. Это включает в себя как исправление невалидного родителя, так и коррекцию "перескока" через уровень иерархии.

## Последствия

- **Положительные:**
  - Высокое удобство для пользователя, который может быстро реорганизовывать структуру.
  - Система "прощает" ошибки пользователя, не заставляя его искать единственно верное место для вставки.
  - Сохраняется чистый и современный UI без лишних кнопок.
- **Отрицательные:**
  - Повышенная сложность логики на стороне бэкенда.
  - В редких случаях "магия" автокоррекции может привести к результату, который пользователь не ожидал.

## Рассмотренные альтернативы

### 1. Кнопки управления порядком (Вверх/Вниз/Влево/Вправо)

- **Описание:** У каждого элемента есть иконки для перемещения на одну позицию вверх/вниз или для изменения уровня вложенности.
- **Отклонено, т.к.:** Крайне неудобно для больших перемещений, загромождает интерфейс. Несмотря на простоту и предсказуемость, значительно ухудшает пользовательский опыт при реорганизации больших структур.

### 2. Drag-and-Drop с явными ошибками

- **Описание:** Пользователь перетаскивает элементы, но если перемещение невалидно, оно отменяется и выводится сообщение об ошибке.
- **Отклонено, т.к.:** Хотя этот подход более предсказуем, он может вызывать раздражение у пользователя, который вынужден методом проб и ошибок искать корректное место для вставки, не получая помощи от системы.

### 3. Гибридный D&D с визуальной обратной связью

- **Описание:** Во время перетаскивания валидные места для вставки подсвечиваются зеленым, а невалидные — красным.
- **Отклонено, т.к.:** Признан "идеальным" вариантом с точки зрения UX, но его реализация на порядок сложнее остальных. Она потребовала бы использования более низкоуровневых библиотек для D&D и значительного усложнения логики на фронтенде, что выходит за рамки текущей задачи.

### 4. Модальное окно с текстовым редактированием

- **Описание:** Структура повествования выводится в виде текстового списка с отступами. Пользователь редактирует текст и применяет изменения.
- **Отклонено, т.к.:** Несмотря на потенциальную мощь для массовых правок, этот способ крайне подвержен ошибкам пользователя (опечатки, неверные отступы) и требует очень сложной, нетривиальной логики парсинга и "примирения" на бэкенде. Риск потери или повреждения данных слишком высок.
