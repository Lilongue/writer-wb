# Журнал разработки

Этот файл содержит хронологию выполненных работ по проекту.

---

## 10 Февраля 2026 г

* **Опционально создаем подпапку для нового проекта:** Добавлена опция в мастер создания проекта, позволяющая пользователю указать, создавать ли новый проект в подпапке с его именем. Реализована санитаризация имени проекта для использования в качестве имени папки.

## 05 февраля 2026 г

* **Настройка пути к внешнему редактору:** Реализована возможность указания пользователем пути к внешнему редактору Markdown в настройках проекта. В случае, если путь указан, файл открывается с использованием заданного редактора; в противном случае используется системное приложение по умолчанию. Добавлен диалог выбора файла в UI настроек.

## 02 февраля 2026 г

* **Рефакторинг настроек проекта:** Проведен рефакторинг системы настроек проекта. В модель данных `ProjectSetting` добавлено поле `uiHint`, разделяющее тип данных (`type`) от его визуального представления. Модифицирован UI (`ProjectSettingsModal`) для отображения полей `readonly`, `file-path` и `textarea` с соответствующими стилями. В схему БД и DAO внесены изменения для поддержки нового поля. При создании проекта теперь автоматически сохраняется версия приложения в `readonly` поле.

* **Синхронизация выбора в деревьях:** Исправлена ошибка, из-за которой выбор элемента в дереве "Объекты мира" не снимал выделение с элемента в дереве "Повествование". Рефакторинг `NarrativeTree` был произведен для управления его состоянием выбора через глобальное состояние в `App.tsx`, что обеспечило консистентное поведение выбора по всему приложению.

## 31 января 2026 г

* **Отдельный заголовок для повествования:** Реализована возможность добавлять элементам повествования отдельное поле `title`, которое используется при экспорте рукописи и при создании файла контента. В отличие от поля `name`, `title` является опциональным и может быть пустым. Обновлены DAO, сервисы и UI для поддержки нового поля.

## 28 января 2026 г

* **Стабилизация файловой структуры:**
  * Проведен рефакторинг `WorldObjectService` для использования `template_id` вместо `template_name` в путях к файлам контента (`world/<template_id>/<object_id>/content.md`).
  * Это изменение устранило критическую проблему, при которой переименование шаблона приводило к потере доступа к файлам всех связанных с ним объектов мира.

* **Рефакторинг и унификация UI:**
  * **Модальное окно импорта шаблонов:** Проведен полный редизайн окна импорта. Вместо неинтуитивного двухпанельного интерфейса реализован сеточный макет с карточками шаблонов, что значительно упростило выбор. Добавлена возможность фильтрации по "выбранным" шаблонам.
  * **Очистка кода:** Проведена очистка `WorldObjectModal` и связанной с ним логики от неиспользуемого функционала для работы с дополнительными полями.
  * **Унификация отображения свойств:** Создан универсальный компонент `ObjectProperties.tsx` для стандартизированного отображения пользовательских полей.
  * **Модальное окно создания проекта:** Исправлены отступы сверху и улучшено выравнивание чекбоксов для выбора иерархических уровней, что привело к более равномерному распределению элементов.
  
  * **Расширение функционала и рефакторинг области отображения контента (`ContentDisplay`):**
    * Заголовок (`ContentDisplayHeader`) был изменен: поле для ввода имени объекта/нарратива перемещено в секцию деталей, а сам заголовок теперь содержит только кнопки действий.
    * Добавлена кнопка "Открыть папку объекта", позволяющая открывать директорию, связанную с текущим объектом мира.
    * Кнопка "Открыть во внешнем редакторе", перенесена в заголовок.
    * Обеспечена консистентность отображения полей имени и описания для `WorldObjectDetails` и `NarrativeDetails` после переноса из заголовка.

## 4 января 2026 г

* **Исправление системы уведомлений:**
  * Устранена проблема, из-за которой уведомления `Ant Design` не отображались пользователю. Проблема была связана с отсутствием необходимого контекста в `Ant Design v5+`.
  * Решение реализовано с помощью хуков `useNotification` и `useMessage` в корневом компоненте `App.tsx`. API, полученные от хуков, сохраняются в глобальный `apiHolder`, что делает их доступными для централизованного `notificationService`.

* **Запрет на создание вложенных проектов:**
  * В `ProjectService` добавлена проверка, запрещающая создавать проект в директории, которая уже является проектом.
  * Проверка использует существующий метод `_validateProjectStructure` и в случае ошибки выводит пользователю уведомление через `notificationService`.
