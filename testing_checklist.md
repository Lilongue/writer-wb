# ✅ Чек-лист для тестирования приложения WriterWorldBuilder (обновлённая версия)

Этот чек-лист предназначен для ручного тестирования основного функционала приложения. Охватывает все фичи, помеченные как **✅ Реализовано**.

## 1. Управление проектом

### 1.1. Создание нового проекта

- [ ] 1.1.1. Открыть мастер создания проекта через меню `Файл -> Новый проект`.
- [ ] 1.1.2. Ввести имя проекта и выбрать папку.
- [ ] 1.1.3. Убедиться, что кнопка "Далее" неактивна, если не заполнено имя или не выбрана папка (есть соответствующая надпись).
- [ ] 1.1.4. Оставить структуру повествования по умолчанию (`Часть`, `Глава`, `Сцена`).
- [ ] 1.1.5. Успешно создать проект.
- [ ] 1.1.6. Проверить опцию "Создать подпапку" при создании проекта:
  - [ ] Если опция выбрана, убедиться, что в выбранной папке **создалась подпапка с именем проекта**.
  - [ ] Если опция не выбрана, убедиться, что в выбранной папке **не создалась подпапка с именем проекта**.
- [ ] 1.1.7. Проверить, что внутри папки проекта есть:
  - `project.sqlite`
  - папки `narrative`, `world`, `templates`
- [ ] 1.1.8. Проверить, что после создания проекта в дереве повествования есть корневой элемент "Произведение".
- [ ] 1.1.9. Попробовать создать проект в уже существующей папке с проектом (ожидается **ошибка или предупреждение** о существовании проекта).
- [ ] 1.1.10. В мастере создания проекта снять все галочки со структуры повещевания и нажать "Далее" (ожидается, что **кнопка неактивна**, с пояснением).
- [ ] 1.1.11. Проверить, что **в `project.sqlite` корректно заполнены таблицы**:
  - `narrative_structure`
  - `settings`
  - `entity_templates`

### 1.2. Открытие и закрытие проекта

- [ ] 1.2.1. Закрыть приложение и открыть снова. Убедиться, что проект **не открыт автоматически**.
- [ ] 1.2.2. Открыть существующий проект через меню `Файл -> Открыть проект`, выбрав файл `project.sqlite`.
- [ ] 1.2.3. Убедиться, что:
  - дерево повествования загружено
  - дерево объектов мира загружено
  - метаданные (настройки, типы) доступны
- [ ] 1.2.4. Попробовать открыть невалидную папку (без `project.sqlite`) как проект — **ожидается сообщение об ошибке**.
- [ ] 1.2.5. Проверить, что при закрытии приложения (`before-quit`) проект корректно закрывается:
  - база данных закрывается без ошибок
  - не остаётся блокировок файлов
- [ ] 1.2.6. Попробовать открыть повреждённый `project.sqlite` (например, с удалённой таблицей) — **ожидается корректное сообщение об ошибке, приложение не падает**.
- [ ] 1.2.7. При закрытом проекте (сразу после запуска приложения) попробовать открыть настройки проекта (`Файл -> Настройки`). Ожидается, что **действие будет заблокировано и/или появится уведомление**.

- [ ] 2.5. Удалить созданную "Сцену". Подтвердить удаление.
- [ ] 2.6. Выбрать "Главу", в центральной панели ввести текст в поля:
  - "Описание"
  - "План" (добавить 2–3 пункта, один отметить как выполненный)
  - "Основная мысль"
- [ ] 2.7. Выбрать другой элемент дерева, затем вернуться к "Главе". Убедиться, что **все данные сохранились**.
- [ ] 2.8. Для "Сцены" убедиться, что **файл `.md` создался автоматически** при создании сцены.
- [ ] 2.9. Нажать "Открыть в редакторе". Убедиться, что открылся внешний редактор.
- [ ] 2.10. Изменить MD-файл во внешнем редакторе, сохранить его. Убедиться, что **контент в приложении обновился без перезагрузки**.
- [ ] 2.11. Проверить, что **все пути к файлам повествования используют ID**, а не названия (проверить в `project.sqlite`).
- [ ] 2.12. Попробовать создать элемент повествования с пустым именем — **ожидается блокировка действия**.
- [ ] 2.13. Проверить, что при удалении родительского элемента (например, главы) **удаляются и все дочерние элементы (сцены)**, а также связанные файлы.
- [ ] 2.14. Убедиться, что **поле "Заголовок для экспорта" (если реализовано) не влияет на отображение в дереве**, но учитывается при сборке рукописи.
- [ ] 2.15. Проверить массовое добавление пунктов в план:
  - [ ] 2.15.1. Для элемента повествования в секции "План" нажать на добавление нового пункта.
  - [ ] 2.15.2. В открывшемся модальном окне вставить в текстовое поле несколько строк, разделенных переносом строки, включая пустые строки. Например:

    ```text
    Пункт 1
    Пункт 2

    Пункт 3
    ```

  - [ ] 2.15.3. Сохранить.
  - [ ] 2.15.4. Убедиться, что **создано три новых пункта плана**, соответствующие непустым строкам, а **пустая строка проигнорирована**.

### ✅ Рекомендации по тестированию

- Тестировать **на чистой системе** без предустановленных зависимостей.
- Проверять **работу с кириллицей в именах проекта, объектах и путях**.
- Тестировать **на разных ОС** (Windows, macOS, Linux), если возможно.
- Использовать **несколько сценариев с разными структурами повествования** (например, без "Части", только "Глава -> Сцена").
